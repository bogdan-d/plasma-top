# 02: Applet talks to the daemon over D-Bus, and the migration is finished

**What to build:** The Plasma applet consumes the daemon's D-Bus interface from ticket 01 using the pure-QML `org.kde.plasma.workspace.dbus` module, per the [spec](../spec.md): pushed properties for panel/tooltip/page state, async method calls for paging, presentation, and geometry, and a service watcher for daemon restarts. In steady state plasmashell starts no processes for display, paging, or presentation. Installer, packaging, docs, and agent instructions describe the new contract, and the end result is verified live.

**Blocked by:** 01 (Daemon serves the applet over session D-Bus)

**Status:** done

- [x] One `Properties` binding receives `PanelHtml`, `TooltipHtml`, `Page`, and `PageCount`; the `cat` commands, `FolderListModel` watcher, read debounce, and bootstrap timer are removed.
- [x] Received and displayed text are separate: panel text updates from non-empty values; tooltip text updates only while this widget is presented and catches up on presentation; empty values and daemon absence never clear displayed text.
- [x] Method calls use `SessionBus.asyncCall` with `dbusMessage` and explicit signatures `(i)`, `(t)`, `(ddbd)`; geometry is sent only when panel width and both glyph advances are positive.
- [x] On every daemon registration the applet starts a new service lifetime ignoring older replies, forgets cached lease state, calls `updateAll()`, resends geometry, and presents again if presented.
- [x] The wheel calls `StepPage`; the wheel command settings are removed from config, the Appearance page, and installer substitution.
- [x] The presentation-lease component uses `Present`/`Dismiss`, keeps one-in-flight serialization, drops the heartbeat, and still dismisses on destruction, including with a call in flight.
- [x] Middle-click keeps its configurable command and the nonce helper; settings pages keep their existing `plasma-top config` transport.
- [x] Applet minimum Plasma API version, README requirements, and AUR packaging say Plasma 6.8 or newer; the user-install test drops wheel-command assertions; uninstall still removes leftover runtime files from older versions; install/upgrade never delete them.
- [x] New ADR records the session-bus protocol and connection-owned leases; the design, performance, development, and metrics-inventory docs, README, project QML skill rules, and agent-instruction load-bearing contracts are updated; glossary gains presentation lease and applet client if missing.
- [x] The isolated `qml_verify` smoke runs daemon and applet on a private session bus and exercises all three method signatures, initial hydration, a pushed value, daemon restart while presented, and two widgets with only one presented.
- [x] Live verification on a Plasma 6.8 session: panel and tooltip update, wheel paging, pinning, desktop mode, middle-click, multiple widgets, daemon restart, and plasmashell restart all work.
- [x] Performance evidence: a steady-state profile shows no process spawns from plasmashell for display, paging, or presentation, and end-to-end publication latency is no worse than the old file path.
- [x] `shellcheck` and `shfmt` pass on changed shell scripts; full Rust gates pass.

## Comments

- Applet API facts were checked against the Plasma 6.8 module source (`components/dbus`): `asyncCall` takes `{service, path, iface, member, arguments, signature}` and encodes plain JS values against the explicit signature, `Properties` emits `propertiesChanged` for pushed signals and for the `GetAll` that `updateAll()` triggers, and `DBusServiceWatcher` checks registration synchronously at startup.
- The lease component starts as "known, not presented", so a hidden widget never sends a needless `Dismiss`; a failed call makes the lease unknown and waits for the next intent change or daemon registration instead of retrying in a loop.
- `qml_verify.sh --smoke` runs on a private bus with no service directories, because bus activation (kactivitymanagerd, the portal, ksecretd) otherwise outlives the bus and writes into the test root. `plasmawindowed` is a unique application, so the second widget joins the first process and both share one bus connection, as in plasmashell. It shows every widget planar and expanded, so the smoke copies make presentation follow hover alone; one copy hovers, pages, and sends a fixed geometry. `dbus-monitor` records the calls Qt encodes: `StepPage(int32 1)`, `Present(uint64)`, and `SetGeometry(double, double, boolean, double)`. A daemon restart while presented yields exactly one new `Present`, and text is never cleared.
- Performance evidence (isolated `plasmawindowed`, presented, one wheel step every 3 s, `strace -f -e execve`, private bus; old = `2ed38ef`, new = this branch):
  - Process starts from the applet in 60 s: new 0 (only the traced `plasmawindowed` launch), old 218 (a `sh` + `cat` per panel or tooltip read, a `sh` + `plasma-top page next` per wheel step, and lease heartbeats).
  - Publication to QML panel text, 60 s runs: new p50 0.5 ms, p95 1.1 ms (n = 18, from the bus's `PropertiesChanged` timestamp); old p50 55.0 ms, p95 55.9 ms (n = 21, from `panel.html` mtime), dominated by the 50 ms watcher debounce plus the `cat` fork. Harness under `.tmp/perf/`.
- Live session (Plasma 6.8.0, approved by the user): `./install.sh` upgraded the user install, then the service and `plasma-plasmashell` were restarted. On the live bus the new applet sends `SetGeometry` and `Present`, and after a daemon restart it resent geometry and presented again within about 0.5 s; `StepPage`, `Present`, and `Dismiss` arrived while the widget was used. plasmashell logged no PlasmaTop errors, and 15 s of child-process polling showed no PlasmaTop processes. After the graphs flicker fix and the API-version revert, the user removed the widget, ran `./uninstall.sh` and `./install.sh`, re-added the widget, and confirmed everything works with no flicker.
- Live finding: entering the graphs page, or presenting it again, briefly shrank the tooltip. The scheduler published the page immediately (pending-page placeholder, no charts) and again about 5 ms later when `PageRender` finished; the old applet's 50 ms watcher debounce had hidden the first frame. The scheduler now skips the immediate `PageChanged`/`TooltipActivated` publication while activation work is pending and lets the completion or the 100 ms timeout publish, since the applet already shows its retained tooltip. Profiling stimuli whose transition defers publication complete on that deferred `TooltipRefresh`. Verified in isolation (main page 639 px straight to graphs 998 px) and installed live.
- Deviation: `X-Plasma-API-Minimum-Version` stays `6.0`. Setting it to `6.8` made Plasma 6.8's widget explorer list the applet as "Unsupported Widget" ("written for Plasma 6.8 and is not compatible with the older version of Plasma installed"), because the field is compared against the applet API version rather than the Plasma release; every applet shipped with Plasma 6.8 declares `6.0`. The Plasma 6.8 minimum is stated by the README and the AUR dependency, and an older Plasma fails visibly on the missing `org.kde.plasma.workspace.dbus` import.
- Codex review (`gpt-6.1-sol`, xhigh) found four P2 issues, all confirmed and fixed: the rewrite had dropped `Plasmoid.onActivated` (keyboard and accessibility activation), now restored; a deferred profiling stimulus could stall when its refresh merged into a coincident `DisplayDeadline` publication, so it now completes on the next tooltip publication of any reason (new unit test); the docs overstated profiling's bus isolation (notifications still go out) and PERFORMANCE.md still described inotify page changes and a retained `tooltip.html`, both corrected along with the profiling report's write-time label.
